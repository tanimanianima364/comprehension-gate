# The supported host is Linux, not POSIX in general

## What this change was for

The README said "POSIX only", which claims more than anything here exercises.
The plugin is run from WSL and its tests run there and on an Ubuntu runner;
nothing else has been tried and kept. The user asked for the claim to match:
Linux (WSL) only.

## The approach, and what it rejected

The claim is narrowed rather than the testing widened. A second runner for
another POSIX host was the alternative, and it was tried and withdrawn: the
user does not want the coverage, and the run showed the runner exercising a
different git than the one it was said to exercise -- a claim of coverage
that was itself untrue. A scope statement that names only what is tested
cannot go wrong that way.

This refines the note that took Windows out of scope rather than overturning
it. Everything that note decided still holds -- one POSIX quoting rule for the
rendered command, no separator translation, a backslash as an ordinary
character in a file name -- and all of it is correct on Linux. Only the
breadth of the claim shrinks, so nothing is superseded.

## How it is built

The README's Scope section says Linux, and why. No code changes: what the
code does is POSIX-correct, and Linux is the POSIX it is checked on.
